# 《안개항의 상속자》 대사·스토리 스크립트

> 이 폴더는 게임 빌드의 기반이 되는 **대사·분기·퀘스트 스크립트 정본**이다.
> 상위 기획은 [`../GAME_DESIGN.md`](../GAME_DESIGN.md)를 따르며, 이 스크립트는
> 그 기획을 실제 대사·노드·플래그 단위로 구체화한 것이다.
> 세 기획 문서와 이 스크립트가 충돌하면 `GAME_DESIGN.md`의 확정 사항을 우선한다.

## 문서 구성

| 파일 | 내용 |
| --- | --- |
| [`00_SYSTEM.md`](00_SYSTEM.md) | 플래그·변수, 결정적 증거·엔딩 분기 로직, 대사 노드 규약, 복원 퀘스트 데이터 스키마 |
| [`01_PROLOGUE.md`](01_PROLOGUE.md) | 프롤로그 — 사무소 시작, 경찰서 의뢰, 첫 태도 선택 |
| [`02_ACT1.md`](02_ACT1.md) | 1막 사라진 얼굴 — 엘리너·홀트, 고양이 서브, 얼굴 복원 |
| [`03_ACT2.md`](03_ACT2.md) | 2막 지워지지 않는 증거 — 저택 조사, 인장·문신 복원, 핵심 판단 2 |
| [`04_ACT3.md`](04_ACT3.md) | 3막 마지막 항해 — 뱅크스, 부두 현장 복원, 항해일지·고양이 회수, 핵심 판단 3 |
| [`05_FINALE_ENDINGS.md`](05_FINALE_ENDINGS.md) | 최종 국면 증거판, 결론 선택, 엔딩 A/B, 엔딩 후 재시작 |
| [`06_SIDE_NPCS.md`](06_SIDE_NPCS.md) | 주변 NPC 대표 대사 샘플, 야외 이동 NPC |

## 읽는 순서

1. 먼저 `00_SYSTEM.md`에서 **플래그·노드 규약·엔딩 조건**을 이해한다.
2. `01`~`05`는 플레이 순서 그대로 읽으면 전체 흐름이 파악된다.
3. `06`은 메인 경로와 독립적으로 배치되는 생활감·보조 단서 대사다.

## 빌드로 옮길 때

- 각 대사 노드는 `id`로 고유 식별된다. 대화 데이터를 JSON/테이블로 옮길 때 이 id를 키로 사용한다.
- 분기·잠금·증거 획득은 모두 `00_SYSTEM.md`에 정의된 **플래그**로만 처리한다.
  스크립트 본문의 `결과` 열에 적힌 플래그 조작을 그대로 구현하면 분기가 재현된다.
- 복원 퀘스트의 `그림 근거` 표는 "어떤 증언·단서가 캔버스의 어떤 특징을 해금하는가"를
  정의한다. 복원 목표(HUD)와 숨은 채점 필수 특징이 이 표에서 파생된다.
