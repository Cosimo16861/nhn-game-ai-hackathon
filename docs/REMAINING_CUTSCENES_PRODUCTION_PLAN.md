# 남은 컷신 전체 제작 계획

> 기준일: 2026-08-09
> 범위: 승인된 `C0B_THE_JOB`을 제외한 컷신 전편(현 그래프 기준 20개 예상)
> 목적: 모든 퀘스트 통과 뒤 컷신이 실제로 재생되고, 다음 복원에 필요한 증언·근거를
> 자연스럽게 획득한 뒤 다음 노드가 열리는 완주 가능한 흐름을 만든다.

## 0. 이번 계획의 결론

현 그래프에는 한 퀘스트가 다음 레이어의 두 퀘스트를 여는 지점이 네 곳 있다. 이때 한 편에
두 복원 당위를 몰아넣지 않고 **다음 퀘스트 하나당 컷신 한 편**을 만든다. 그러므로 기존
17편 체계를 그대로 세면 안 되며, 4개의 다중 목적지 컷신을 각각 2편으로 분리한 21편
(승인된 C0B 포함)을 현 기준 예상치로 삼는다.

제작은 레이어 경계 단위로만 진행한다. 한 경계에 필요한 모든 목적지별 컷신을 만든 뒤
독립 검토 화면에서도 실제 플레이처럼 묶음 전체를 고정 순서로만 재생하고 사용자 승인을
기다린다. 승인 전에는 게임 진행, 저장 플래그, 해금에 연결하지 않는다. 사용자가 재개를 요청했을 때만 다음 레이어
경계로 이동하며, 전편 검토가 끝난 뒤 별도 통합 단계에서 실제 게임에 삽입한다.

```text
정본 충돌 해소
→ 목적지별 증언 계약 확정
→ L0→L1 전편 제작·검토·승인
→ 사용자 재개 요청
→ L1→L2 전편 제작·검토·승인
→ 같은 방식으로 마지막 레이어까지 반복
→ 전편 승인 후 공통 재생기·진행 원자성 통합
→ 전 경로·전 순서 통합 QA
```

최종 산출물은 컷신 이미지 묶음만이 아니다. 컷신 데이터, 공통 재생기, 증언 플래그,
실제 복원 결과 삽입, 스킵·재개·해금 테스트, 대본과 퀘스트의 정합성 검사까지 한 단위로
완료해야 한다.

## 1. 범위와 예외

### 1.1 제작 대상 수 산정

- 기존 기준: 오프닝 2편(C0, C0B) + 퀘스트 완료 컷신 15편 = 17편
- 목적지별 분리 추가분: Q0, Q1A, Q2A, Q3A가 각각 자식 둘을 열므로 +4편
- 변경 후 예상: 총 21편, 승인된 C0B 제외 신규·재제작 20편
- 사용자 승인 완료: L0→L1 2편, L1→L2 3편

`C0B_THE_JOB`은 새로 만들지 않고 공통 화면·입력·타이밍의 승인 기준으로 사용한다.

### 1.2 “모든 컷신은 다음 퀘스트를 위해 존재한다”의 적용

- `bridge`: 목적지 퀘스트 **하나**의 복원 당위와 입력 증언만 담당한다.
- 부모 하나가 자식 N개를 열면 bridge N편을 그래프의 고정 순서로 연속 재생한다.
- 중간 컷신을 스킵해도 다음 컷신으로 넘어가며, 큐 전부가 종료·스킵되기 전에는 어떤 자식도
  해금하지 않는다.
- `closing`: 새 노드를 열지 않더라도, 현재 남아 있는 플레이 가능 노드로 돌아갈 이유를
  상태에 맞는 한 줄로 상기시킨다. 이미 해당 노드를 끝냈다면 거짓 단정을 하지 않는다.
- `opening`: `C0 → C0B → Q0`의 직업·의뢰 인과를 만든다.
- `ending`: 다음 퀘스트가 없는 유일한 종결 예외다. 새로운 단서를 추가하지 않고 플레이어가
  이미 복원한 증거의 결론만 회수한다.

### 1.3 정본 우선순위

충돌이 있을 때 아래 순서를 따른다.

1. 이번 세션의 사용자 조건
2. `docs/STORY_OUTLINE.md`의 진실·공개 순서
3. `docs/script/07_CUTSCENES.md`의 장면·대사
4. `docs/RESTORATION_QUEST_SPEC.md`의 다음 작업대 입력·하드 게이트
5. `src/data/quest-graph.js`의 노드·부모·해금 구조
6. 승인된 실제 기준점 `src/cutscene-c0b.js`와 `docs/C0B_EVALUATION_LOG.md`
7. 나머지 연출·이미지 계획 문서

하위 문서가 상위 기준과 다르면 구현에서 조용히 절충하지 않고 문서와 검증 fixture를 함께
고친다.

## 2. 현 상태 조사 결과

### 2.1 구현된 것

- `C0B_THE_JOB` 한 편이 640×384 캔버스, 이미지 배경·인물 레이어, 고해상도 텍스트
  레이어, 타이핑, 자동 진행, `SPACE` 2단계 입력, `visualLock`, 스킵 완료 콜백까지 갖췄다.
- C0B 최종 영상은 640×384, 약 28.8초이며 3회 평가 후 9/10을 받았다.
- 퀘스트 그래프에는 15개 노드와 기존 17개 전체 컷신의 `UNLOCKS`, 대기 컷신 탐색,
  형제 순서 독립 규칙이 들어 있다. 목적지별 컷신 큐 구조로 바꾸는 일은 전편 승인 뒤 통합
  단계로 보류한다.
- 증거판은 640×384 도트 화면과 노드 공개 규칙을 구현했다.
- 기존 컷신 17개의 대본, 화면 연출안, 이미지 목록, 복원 퀘스트별 목표 명세가 문서로 존재한다.
- C0B 게임용 자산은 배경 1장과 플레이어·리드 포즈 6장만 준비되어 있다.

### 2.2 아직 구현되지 않은 것

- 공통 `src/cutscene.js`와 `src/data/cutscenes.js`가 없다.
- C0B 외에는 게임에 연결된 컷신이 없다. 다만 L0→L1 검토용 두 편과 전용 최종 자산은
  게임 저장소와 분리된 상태로 제작되어 있다.
- 표준 작업대 등록 형식으로 실제 연결된 퀘스트는 현재 `Q0_MONTAGE` 하나뿐이다.
- 나머지 복원 데이터 중 일부는 과거 `REST1/2/3` 형식이며 새 노드 ID·명세와 아직 통합되지 않았다.
- 실제 복원 결과를 컷신 삽입 컷과 증거판 썸네일로 불러오는 저장 API가 없다.
- 정확한 글자, 파도 3줄·4줄, 조건부 비트, 조건부 후일담을 공통 데이터로 검증하는 도구가 없다.

### 2.3 즉시 고쳐야 할 충돌

| 항목 | 현재 상태 | 계획에서의 결정 |
| --- | --- | --- |
| 완료 처리 | `WorkbenchFlow.complete()`가 컷신을 재생하지 않고 `CUTSCENE_SEEN_*`를 즉시 기록 | 퀘스트 통과 시 `NODE_CLEARED_*`만 기록하고 컷신 화면으로 이동. 컷신 종료·스킵 시에만 grants와 seen을 원자적으로 기록 |
| 대사창 규격 | 문서는 448×112, 승인된 C0B 코드는 `x=152, y=278, 336×84` | **실제 C0B 규격을 정본**으로 고정. 모든 남은 컷신이 같은 상자·이름표·폰트·3배 텍스트 레이어 사용 |
| 스킵 | 기존 문서는 첫 관람 스킵 금지 | 이번 조건에 따라 **첫 관람 포함 항상 스킵 가능**. 버튼과 `ESC`를 항상 노출하고 스킵도 정상 종료로 취급 |
| 해상도 | 퀘스트 그래프·자산 명세·복원 명세의 일부 `gridSize`가 서로 다름 | 컷신 제작 전 노드별 정본 크기를 한 표로 잠그고 코드·자산 manifest를 교차 검증 |
| 비트 수 | `07_CUTSCENES.md`의 머리말 비트 수와 실제 표의 발화 행 수가 다수 불일치 | 실제 데이터 행과 무대 지시를 기준으로 재산정. 길이는 숫자를 맞추기 위해 대사를 삭제하지 않고 읽기 시간으로 산출 |
| 증언 시점 | 여러 퀘스트의 작업대 메모가 직전 컷신에 아직 등장하지 않음 | 3장의 증언 계약에 따라 대본을 보강한 뒤 자산 제작 시작 |

### 2.4 현재 테스트 기준선

- Node 테스트 4개는 통과한다.
- Python 복원 자산 테스트는 코드 실패가 아니라 실행 환경에 `numpy`가 없어 시작하지 못한다.
- 현재 `workbench-flow` 테스트는 잘못된 즉시 컷신 완료 동작을 정답으로 고정하고 있으므로
  진행 계약 수정과 함께 기대값을 바꿔야 한다.

| `C6_EVIDENCE_WALL` | Q5A | Q6 | Q5A의 4줄과 Q3A의 3줄, 카버가 배운 것은 마차 문양이라는 관계, 모든 그림을 벽에 걸고 마지막 실을 이어야 법적 틈을 막을 수 있음 | 마차 소유자 이름과 “방계 문장” 해설은 금지. 현재 대본의 방계 설명은 등록부 공개 뒤 CE로 이동해 Q6 전에 줄리언을 사실상 지목하지 않게 함 |
| `C6B_THAT_NIGHT` | Q5B | 남아 있는 본선 또는 복귀 | 복원 결과가 증언과 맞고, 에드먼드는 영웅이 아니라 두려운 18세였다는 확인. 미완료 본선이 있으면 사건으로 돌아갈 중립적 이유 | 본선을 전혀 하지 않고 도달 가능한 상태를 포함해 조건부 복귀 문구 검사 |
| `CE_ENDING` | Q6 | 없음 | 등록부 소유자 이름, 3줄·4줄·카버의 4줄·`T.C.`를 이미 얻은 순서대로 결론화 | 새로운 범인·새 증거·새 복원 입력을 만들지 않음. 조건부 후일담만 추가 |

### 3.1 증언 ID 규칙

각 작업대 메모는 문자열만 복사하지 않고 안정된 ID로 연결한다.

```text
CUTSCENE beat 또는 grant
  → testimonyId: TEST_Q2A_SCAR
  → source: HOLT
  → acquiredAt: C2A_WHAT_WAS_ERASED
  → Workbench Q2A quote
  → region/hard-gate 설명
```

- 작업대의 모든 필수 `quote`는 직전까지 재생 가능한 컷신의 `testimonyId`를 참조한다.
- 현장 관찰은 `OBS_*`, 인물의 발언은 `TEST_*`, 물증은 `EV_*`로 나눈다.
- 조건부 보조 증언은 별도 `optional: true`로 두고 통과 하드 게이트를 늘리지 않는다.
- `C0B → Q0`의 상세 마르타 증언만 기존 튜토리얼 예외로 유지한다.

## 4. 동결할 공통 컷신 규격

### 4.1 화면

- 논리 해상도: 640×384
- 배경: 640×384 불투명 PNG 또는 같은 규격의 코드 배경
- 텍스트: 1920×1152 투명 캔버스에 3배 렌더 후 합성
- 대사창: `x=152, y=278, w=336, h=84`
- 이름표: C0B의 패널 모양·위치·화자색을 그대로 사용
- 본문: C0B 기준 14px/3배 레이어, 최대 3줄. 실제 폰트 폭으로 사전 줄바꿈 검증
- 이미지 보간: 항상 끔, 모든 배치·크롭은 정수 좌표
- 핵심 증거 안전 영역: 대사창 위 중앙을 우선 사용하되, 장면별 실제 가림 검사를 수행

문서의 기존 448×112 수치는 실제 승인본과 다르므로 관련 문서를 함께 정정한다. 배경 제작은
하단 112px에 핵심 단서를 두지 않는 보수적 안전 영역을 계속 사용해도 되지만, 화면에 그리는
대사창 자체는 C0B의 336×84로 통일한다.

### 4.2 입력·자동 진행·스킵

- 자동 진행은 유지하되 글자 완성 뒤 최소 0.8초를 보장한다.
- `SPACE`/클릭 1회는 현재 문장 완성, 다음 1회는 다음 비트다.
- 입력 잠금 120ms와 장면별 `visualLock`을 유지한다.
- 첫 관람을 포함해 `ESC`와 화면의 `건너뛰기` 버튼을 항상 제공한다.
- 스킵은 마지막 프레임으로 억지 점프하지 않고 공통 `finalize({ skipped: true })`를 한 번 호출한다.
- 자연 종료와 스킵 모두 같은 grants·seen·unlocks·다음 화면 이동을 수행한다.
- 오류로 자산을 못 불러온 경우에는 텍스트·도형 fallback으로 계속 진행하고 오류를 기록한다.

### 4.3 카메라와 극적 변주

기본 다섯 모드 `world`, `third-person`, `first-person`, `evidence`, `memory`를 유지한다.
대사창은 어떤 모드에서도 움직이지 않는다.

- 관계·부탁: `third-person`
- 직접 증언·고백·반박: `first-person`
- 정확한 모양·문자·차이: `evidence`
- 과거 목격: `memory`
- 장소·입퇴장·여운: `world`

극적 효과는 C3A, C6, C6B, CE에 집중한다. 흔들림·단계 줌·1~2프레임 플래시는 핵심 사실
공개에만 쓰며 대사창은 흔들지 않는다. 광과민·감소 모션 설정에서는 테두리 강조와 정지로
대체한다.

### 4.4 런타임과 영상 파일의 관계

게임에서 재생되는 캔버스 런타임을 정본으로 삼는다. 매 컷신을 WebM으로 따로 렌더해 다시
재생하지 않는다. 그렇게 하면 조건부 비트, 실제 복원 결과, 접근성 텍스트, 스킵·재개 상태가
영상과 갈라진다. WebM 캡처는 C0B처럼 타이밍·디코딩·육안 평가용 산출물로만 선택 생성한다.

## 5. 공통 데이터·코드 구조

### 5.1 파일

```text
src/
  cutscene.js                  # 공통 재생기
  cutscene-router.js           # 진입·종료·재개·증거판 이동
  data/
    cutscenes.js               # 현 그래프 기준 21개 데이터, C0B도 최종적으로 같은 스키마로 이관
    testimonies.js             # 증언·관찰·물증 정본
assets/cutscenes/
  backgrounds/<place>/
  portraits/<character>/
  inserts/<group>/
  symbols/
  source/
  cutscene-assets.json
tests/
  cutscene-data.test.cjs
  cutscene-flow.test.cjs
  cutscene-logic.test.cjs
```

프로덕션 진입점은 `cutscene.html?id=<CUTSCENE_ID>` 한 장으로 통일한다. 직접 URL 진입은 현재
pending 컷신과 일치하거나 명시적 replay 모드일 때만 허용한다. 별도의
`cutscene-test.html`은 ID, 플래그, 복원 결과 fixture를 바꿔 각 장면을 독립 확인하되 실제
진행 저장소를 변경하지 않는다. 이 하네스가 있어야 미구현 다음 퀘스트 때문에 컷신 제작 전체가
막히지 않는다.

초기에는 C0B 래퍼가 기존 구현을 호출해도 되지만, 모든 동작이 검증된 뒤 공통 재생기에
흡수해 중복 상태 기계를 남기지 않는다.

### 5.2 데이터 최소 스키마

```js
{
  id,
  kind,
  triggerQuest,
  shots: [{ id, view, background, state, beatRange, staging, insert, effect }],
  beats: [{ who, face, text, duration, textDelay, visualLock, when, testimonyIds }],
  grants,
  unlocks,
  nextRoute,
  spoilerLevel
}
```

- 한 숏이 여러 비트를 소유하게 해 대사마다 구도가 흔들리는 것을 막는다.
- 정확한 문자와 3줄·4줄 문양은 이미지에 굽지 않고 `overlay` 정본으로 그린다.
- `when`은 `if`, `unless`와 종료 컷신용 허용 목록만 지원한다. 임의 함수를 넣지 않는다.
- 모든 asset key는 manifest에 존재해야 하며, 없는 키는 빌드 검증에서 실패한다.

### 5.3 진행 원자성

```text
퀘스트 통과
→ NODE_CLEARED_Qx 저장
→ 목적지별 completionCutscenes 큐로 라우팅
→ 큐의 컷신을 고정 순서로 재생 또는 개별 스킵
→ 마지막 컷신 종료 뒤 grants + 각 CUTSCENE_SEEN_Cx를 한 트랜잭션처럼 적용
→ 자식 노드 상태 재계산
→ 증거판 또는 다음 지정 화면
```

- 컷신 큐 중 창을 닫으면 완료한 편의 재생 위치는 기록할 수 있지만 grants를 적용하지 않는다.
- 재접속 시 `QuestGraph.pendingCutsceneQueue()`가 큐의 첫 미완료 편부터 증거판보다 먼저 재생한다.
- finalize 중복 호출을 멱등 처리한다.
- 스킵도 완료이므로 해금된다. “스킵 가능”과 “진행 유실 없음”을 동시에 만족해야 한다.
- 자산 preload가 끝나기 전에 즉시 스킵해도 finalize가 정상 동작해야 한다.

  부두 인부

- 정본 오버레이: 3줄 본가 문장, 4줄 방계 문장, 닻, `T.C.`, 일지 문구, 등록부 이름,

### 6.3 자산 승인 게이트

각 묶음은 다음을 통과하기 전 다른 표정을 대량 생성하지 않는다.

2. C0B와 팔레트·픽셀 군집·광원 비교
3. 1배와 정수 확대에서 실루엣·한글 판독 확인
4. 대사창과 핵심 증거가 겹치지 않는지 확인
5. 스포일러 금지 정보가 배경·소품에 우연히 들어가지 않았는지 확인

## 7. 단계별 실행 계획

### 단계 A — 정본과 증언 계약 잠금

1. 3장의 표를 기준으로 `07_CUTSCENES.md` 대사를 보강한다.
2. `RESTORATION_QUEST_SPEC.md`의 메모마다 출처 컷신·증언 ID를 붙인다.
3. Q3B가 참조하는 “에드먼드의 옛 닻 문신” 원본이 실제 설정에 없음을 해결한다. 새 물증을
   억지로 만들지 않는 한, Q3B는 카버가 현재 보여 준 문신의 기록과 신선도 관찰로 한정한다.
4. `quest-graph.js`, 복원 명세, 자산 명세의 gridSize를 한 표로 통일한다. 우선 정본 후보는
   `RESTORATION_QUEST_SPEC`의 `64/128` 체계다: Q0·Q2B·Q3B·Q4C는 64, 나머지 복원은 128.
   다른 크기를 유지할 이유가 있으면 이미지 제작 전에 명세와 그래프를 함께 바꾼다.
5. C0B 실제 UI 수치와 이번 스킵 정책을 연출 문서에 반영한다.
6. 각 컷신의 실제 발화 수와 예상 재생 시간을 다시 산출한다.

완료 기준: 다음 작업대 필수 메모 중 출처 없는 항목 0개, 해상도 충돌 0개, 금지 정보 선공개 0개.

### 단계 B — 레이어별 독립 제작·검토

1. 현재 경계의 부모→자식 간선을 모두 열거한다.
2. 자식 하나당 출처·증언·복원 당위 계약을 한 장으로 잠근다.
3. 해당 경계의 컷신을 전부 제작한다.
4. 저장소와 분리된 전체 화면 검토 페이지에서 묶음 연속 재생, 현재 편 스킵, `R` 묶음
   재시작을 제공한다. 외부 제목·재생·조작·현재 컷신 패널은 두지 않는다.
5. 이야기·시각·재생의 세 차례 자체 검토와 수정 기록을 남긴다.
6. 사용자에게 결과를 제시하고 승인 또는 수정 요청을 기다린다.

완료 기준: 해당 경계의 모든 목적지 컷신을 사용자가 각각 확인할 수 있고, 게임 진행 데이터는
변경되지 않는다. 사용자 재개 요청 전에는 다음 경계로 넘어가지 않는다.

### 단계 C — 경계 진행 순서

1. L0→L1: `C1A_RETURNED_HEIR`, `C1B_TWELVE_YEARS_UNDER` — 사용자 승인 완료
2. L1→L2: Q1A 뒤 2편 + Q1B 뒤 1편 — 사용자 승인 완료
3. L2→L3: Q2A 뒤 2편 + Q2B 뒤 1편 + Q2C 뒤 closing 1편
4. L3→L4: Q3A 뒤 2편 + Q3B 뒤 closing 1편 + Q3C 뒤 1편
5. L4→L5: Q4A·Q4B 뒤 각 1편 + Q4C 뒤 closing 1편
6. L5→L6: Q5A 뒤 1편 + Q5B 뒤 closing 1편
7. L6→종결: Q6 뒤 `CE_ENDING`

각 번호는 별도 작업이다. 한 번호의 전편 검토가 끝난 뒤 사용자가 작업 재개를 요청해야 다음
번호를 시작한다. 같은 부모에서 나온 여러 편은 표의 자식 순서대로 연속 재생한다.

### 단계 D — 전편 승인 후 게임 통합

1. `quest-graph.js`의 단일 `cutscene` 필드를 순서 있는 `cutscenes` 배열로 바꾼다.
2. 컷신 큐, 중도 재개, 자연 종료·개별 스킵, 멱등 finalize를 공통 재생기에 구현한다.
3. 마지막 컷신이 끝난 뒤에만 그 큐가 담당한 자식들을 한 번에 해금한다.
4. 승인된 검토용 자산·대본을 변경 없이 게임 데이터로 이관한다.
5. 다음 작업대의 모든 필수 메모가 앞 컷신의 testimony ID를 참조하도록 연결한다.

완료 기준: 직전 실제 복원 결과가 컷신에 보이고, 컷신에서 받은 증언이 다음 작업대에 나타나며,
큐 종료 뒤 정확한 노드만 열리는 것까지 전 경로에서 연속 플레이된다.

### 단계 G — `C0_INTRO` 재제작

공통 런타임과 플레이어 정체성이 안정된 뒤 C0를 C0B 언어로 옮긴다. office를 재사용하고

## 8. 효율적인 세션 운영

### 8.1 작업 단위

한 세션은 아래 중 하나만 완료한다.

- 정본 대사·증언 계약 2~3편
- 공통 런타임 기능 1개와 테스트
- 배경 1곳 또는 인물 1명의 전 표정
- 레이어 경계 1곳의 목적지별 컷신 전편 제작·검토
- 같은 장소의 짧은 closing 2편
- 전체 경로 회귀 fixture 1묶음

세션 끝에는 변경 파일, 통과 테스트, 남은 차단 요소를 기록한다. 완성 이미지가 없는 상태에서
다음 컷신으로 넘어가지 않는다.

### 8.2 토큰·시간 절약 규칙

- 대본을 매번 재해석하지 않고 3장의 증언 ID를 정본으로 사용한다.
- 공통 shot preset과 portrait staging을 데이터로 재사용한다.
- 같은 장소 배경은 상태 오버레이만 바꾼다.
- 인물 calm 승인 후 tense/high를 파생한다.
- 플레이어 실제 복원 결과를 컷신·증거판·엔딩에 한 번 저장해 세 군데서 재사용한다.
- 정확한 문자·문양은 작은 수동 오버레이 하나를 여러 컷에서 재사용한다.
- 본선 파일럿이 승인되기 전 배경·초상을 전량 생성하지 않는다.
- 각 단계 종료 시 자동 정합성 검사로 뒤 단계의 수동 재검수를 줄인다.

### 8.3 우선순위

- P0: 진행 원자성, 증언 출처, C1, C2A, C3A, C4A, C5A, C6, CE
- P1: C2B, C3B, C4C, C5B, C6B
- P2: C3C, C4B, C5C, 조건부 후일담
- C0는 시각적으로 중요하지만 이미 동작하는 오프닝이 있으므로 공통 런타임 안정화 뒤 배치한다.

## 9. 검증 규칙

### 9.1 자동 검사

- 전체 퀘스트 노드에 순서 있는 completion cutscene 큐가 정확히 1개 존재
- 자식이 있는 부모는 자식 수와 목적지별 bridge 수가 같음
- 전체 컷신 ID·shot ID·asset key 중복 0개
- `QuestGraph.UNLOCKS`와 컷신 데이터 `unlocks` 완전 일치
- 다음 작업대 필수 quote의 source testimony 존재
- testimony 획득 시점이 작업대 진입보다 늦지 않음
- 조건부 비트의 플래그가 실제 그래프에 존재
- 3줄·4줄·줄리언 이름·`T.C.` 최초 공개 시점 준수
- 대사창 실측 줄바꿈 3줄 초과 0개
- 자연 종료·스킵 finalize 1회

### 9.2 컷신별 수동 평가 16점

| 항목 | 2점 기준 | 치명 |
| --- | --- | :--: |
| 도트 통일 | C0B와 팔레트·픽셀 밀도·광원이 같은 게임으로 보임 | ● |
| 대사창 동일 | 위치·크기·이름표·폰트·타이핑이 C0B와 동일 | ● |
| 다음 퀘스트 당위 | 해금하는 모든 노드에 왜 그려야 하는지가 있음 | ● |
| 증언 출처 | 작업대 필수 메모가 실제 장면에서 획득됨 | ● |
| 공개 순서 | 결정적 사실과 범인 이름을 앞질러 말하지 않음 | ● |
| 논리 독립 | 형제 완료 순서와 관계없이 대사가 참임 | ● |
| 호흡·초점 | 읽기 시간과 증거 관찰 정지가 충분하고 초점이 하나임 |  |
| 조작 안정 | 자동·SPACE·클릭·스킵·재개가 같은 결과를 냄 | ● |

13/16 이상이고 치명 항목 0점이 없어야 통과한다.

### 9.3 전체 완료 정의

- C0B 제외 20개 컷신이 모두 공통 재생기로 재생된다.
- 모든 컷신은 첫 관람부터 스킵 가능하다.
- 퀘스트 통과 직후 해당 컷신이 재생되고, 종료 또는 스킵 뒤에만 다음 노드가 열린다.
- 다음 작업대의 모든 필수 증언·근거는 앞 컷신에서 출처가 확인된다.
- 본선, 가지 선행, 형제 역순, 중도 종료에서 논리 모순과 진행 막힘이 없다.
- 실제 복원 결과가 뒤 컷신·증거판·엔딩에 재사용된다.
- 정확한 문자와 문양은 수동 정본이며 이미지 생성 오류가 없다.
- 관련 자동 테스트와 시각 평가 기록이 모두 남아 있다.

## 10. 자체 검토 기록

이 장은 초안 작성 뒤 세 차례 검토하며 갱신한다.

### 1차 — 범위·누락 검토

**결과: 새 규칙 반영 후 통과.** `07_CUTSCENES.md`의 기존 17개 ID와
`quest-graph.js`의 15개 노드 완료 컷신을 다시 대조했다. 자식 둘을 여는 Q0, Q1A, Q2A,
Q3A의 bridge를 각각 두 편으로 분리하면 총 21편, 승인본 C0B 제외 제작 대상 20편이다.
네 closing(`C3C`, `C4B`, `C5C`, `C6B`)과 오프닝·엔딩의 “새 자식 없음”은 누락이 아니라
명시적 예외로 유지한다.

추가 확인 항목:

- Q0, Q1A, Q2A, Q3A만 자식을 2개씩 열며 각각 목적지별 두 편으로 분리한다.
- C2B, C3B, C4C, C5A, C5B, C6은 자식을 1개씩 연다.
- C3C, C4B, C5C, C6B, CE는 `UNLOCKS`가 비어 있다.
- C0는 C0B로, C0B는 Q0로 이어지는 경계 흐름이 별도로 기록되어 있다.

### 2차 — 인과·스포일러 검토

**결과: 네 가지 논리 누수를 찾아 수정 후 통과.** 작업대 메모와 직전 컷신을 역대조했다.

- Q3B가 “에드먼드의 옛 문신과 같은 닻”이라고 판정할 독립 원본이 현재 이야기에는 없다.
  계획을 카버의 현재 문신 기록과 새 잉크 관찰로 축소하고, 정본 잠금 단계의 결정 항목으로 올렸다.
- C4A에서 `T.C.`를 미리 읽으면 Q4A 복원의 발견을 선취하므로, 컷신 입력은 “넉 달 치
  지급행의 남은 획”까지만 보여 주고 `T.C.` 판독은 C5A로 유지했다.
- Q4B의 작업대 화자가 아직 만나지 않은 뱅크스로 적힌 출처 오류를 발견해 코라·현장 관찰로
  수정하도록 명시했다.
- C6의 현재 대사 “방계는 문장이 다릅니다”는 출처가 없고 줄리언을 Q6 전에 사실상 지목한다.
  이 설명을 CE의 등록부 공개 뒤로 옮기고, C6은 “카버가 마차 문양을 배웠다”까지만 말하게 했다.

공개 순서는 `C3A 카버의 4줄 주장 → Q3A/C4A 진품 3줄 → Q5A/C6 마차 4줄 → Q6 연결
→ CE 소유자 이름·방계 해설`로 고정했다. 선술집 가지에서는 이 사슬의 결정 정보를 하나도
추가하지 않는다.

### 3차 — 실행 가능성·검증 검토

**결과: 실행 경로를 보강한 뒤 통과.** 컷신만 먼저 제작할 때 아직 미구현인 13개 작업대가
전체를 막는 문제가 있어, 실제 진행 저장소와 분리된 `cutscene-test.html` fixture 하네스를
계획에 추가했다. 프로덕션은 `cutscene.html?id=...` 한 진입점으로 고정해 페이지별 중복 UI를
막았다. 또한 런타임 캔버스를 정본으로 하고 WebM은 평가용으로만 두어 조건부 대사와 실제
복원 결과가 영상 파일과 갈라지는 위험을 제거했다.

스킵은 preload 전·도중·재생 중 어느 시점에도 가능하고 같은 멱등 finalize를 거치도록 테스트
범위를 늘렸다. 단계별 상대 작업량과 승인 게이트를 추가해 공통 계약이 불안정한 상태에서
자산을 대량 생성하지 못하게 했다. 마지막으로 서로 다른 gridSize 문서를 그대로 둔 채 컷신
삽입 크롭을 만들 수 없으므로, 복원 명세의 64/128 체계를 우선 정본 후보로 명시했다.
