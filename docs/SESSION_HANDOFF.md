# 세션 인계 — 복원 256×256 전환 (진행 중)

> 작성: 2026-08-07 · 이전 세션 종료 시점
> 이 문서는 **지금 어디까지 됐고, 무엇이 막혔고, 다음에 무엇을 할지**만 담는다.
> 전체 설계는 `GAME_DESIGN.md`, 대사는 `docs/script/`, 그레이박스 경위는
> `docs/GREYBOX_PLAN.md` 참조.

---

## 1. 한 문단 요약

그레이박스(프롤로그~두 엔딩)는 **완성돼 커밋·푸시됐다**(`1e5a61a`). 그 위에서
복원 화면을 **256×256 + 생생한 목격담**으로 바꾸는 작업을 시작했고, 초상 퀘스트
하나가 절반쯤 전환된 상태다. **원본 아트가 채우기식 복원에 맞지 않는다는 사실이
확인되어 아트 제작 방향 결정에서 멈춰 있다.**

---

## 2. 검증 완료 — 손대지 말 것

그레이박스 로직은 직접 검증했고 결함이 없었다.

- **엔딩 판정 10경우 전부 명세 일치.** 항해일지 보정(증거1→유효2→A), 과잉보정
  방지(증거3+일지→보정0), `carver_alone`→항상 B
- **재시작 복귀 정상.** FINAL·KD3 경로 모두 동작. 되돌아가면 이후 복원(REST3)이
  초기화되고 `SEEN_END_*`는 유지된다
- **엔딩 A 완주 확인.** 보유 증거에 따라 대사가 조립된다
- **KD2 잠금 정상.** 장부 미확인 시 정답 C가 회색 + 사유 표시 + 보류 선택지 D
- 확정 제약 준수: 숫자 노출 0, `UI.confirm` 사용, 외부 의존 0, 콘솔 에러 0

⚠️ **단, 처음부터 끝까지 이어서 플레이한 적은 없다.** 구간별 상태 주입으로
검증했다. **실제 완주 1회와 소요 시간 측정은 여전히 미실시**다(목표 15~20분).

## 3. 이번 세션에서 만든 것

| 파일 | 내용 | 상태 |

| `src/restoration.js` | ImageData 렌더링, 채우기 도구, `source` 기반 비동기 퀘스트 준비 | 수정 |

| `index.html` | 격자 CSS 오버레이, artwork.js 로드, 폴백 문구 | 수정 |

### 실행 방법 (중요)

```bash
python3 serve.py 8124
```

`python3 -m http.server`를 쓰면 **브라우저 캐시 때문에 수정이 반영되지 않는다.**
이 함정으로 여러 번 오판했다. 반드시 `serve.py`를 쓸 것.

## 4. 🚧 막힌 지점 — 다음 세션이 먼저 결정할 것

**기존 자산은 채우기식 복원 타깃으로 쓸 수 없다.**

`assets/`의 NPC 초상(`04-teacher-portraits.png` 등)은 **회화풍 일러스트**다.
원본에서 색을 뽑아보면:

```
#604830(800px) #503828(727) #403020(540) #584028(530) #483828(526) …
```

상위 10색이 전부 미세하게 다른 갈색이고 최대 800픽셀뿐이다. **"선으로 둘러싸인
평면 색 영역"이 존재하지 않는다.** 그래서 어떤 팔레트를 씌워도:

- 성기면 → 한 덩어리로 뭉침 (현재: 최대 영역 **16,381px** = 클릭 한 번에 대부분 칠해짐)
- 촘촘하면 → 수백 개 잡음 영역으로 부서짐

밀랍 봉인(`20-broken-wax-seal.png`)은 상대적으로 평면적이라 정상 분해됐다
(선화 15,488px, 영역 3개). 즉 **파이프라인은 정상이고 원본 아트가 조건 미달**이다.

### 선택지

1. **절차 생성으로 평면 초상을 그린다** ← 이전 세션 추천
   - 영역·특징 위치를 정확히 통제할 수 있다. 눈썹·흉터의 위치와 크기를
     통제하지 못하면 게임의 핵심 장치가 성립하지 않는다
   - 복원 대상은 "증언으로 재구성한 그림"이라 사실적일 필요가 없고,
     평면 도트가 오히려 콘셉트에 맞는다
2. 평면 채색 아트를 따로 준비한다 (품질 최선, 아트 작업 선행)
3. 회화풍 원본을 포스터화+윤곽검출로 평면화 (결과가 지저분할 가능성 높음)

## 5. 확정된 설계 (되돌리지 말 것)

- **복원 결과에 숫자를 절대 노출하지 않는다.** 정성 피드백 4단계만
  (`GAME_DESIGN` 8.4). `scripts/score-manager.js`는 숫자를 노출하는 폐기 스펙
- **네이티브 `confirm()`/`alert()` 금지.** 차단 환경에서 조용히 실패한다.
  `src/ui.js`의 `UI.confirm()`을 쓸 것
- **CLIP 제외.** 외부 네트워크 의존 0. `scripts/clip-*.js`는 미사용으로 남겨 둠
- **복원 목표는 설계 용어가 아니라 목격담으로 표시한다.** 이번 세션의 핵심 요구:
  ```
  이전: ◆ 왼눈썹 비대칭
  이후: "웃을 때요, 왼쪽 눈썹만 유독 위로 올라갔습니다." — 홀트
  ```
  퀘스트의 `requiredFeatures[]`에 `speaker`·`quote`·`missNote`를 넣으면
  목표 패널과 실패 피드백 양쪽에 반영된다

### 퀘스트 데이터 스키마 (256² 기준)

```js
window.QuestPortrait = Object.freeze({
  id: "REST1", gridSize: 256,
  source: drawFn,          // (ctx, size, {loadImage}) => void, async 가능
  outline: "#241C17",      // 선화 색 (플레이어가 고를 수 없음)
  minRegion: 24,
  palette: [{ name, hex }],
  requiredFeatures: [{
    id, clue|always, color,   // color → 그 색으로 칠할 픽셀이 자동 산출됨
    label, speaker, quote, missNote,
  }],
  weights, passingScore,
});
```

`restoration.js`의 `resolveQuest()`가 `source`를 보고 `artwork.js`로 준비한다.
**외곽선 색은 양자화 팔레트에 자동 추가된다**(빠뜨리면 선화가 생기지 않는다 — 실제로 겪음).

## 6. 남은 일 (우선순위)

1. **[막힘] 복원 타깃 아트 방향 결정** → 4장 참조. 결정 후 초상 퀘스트 완성
2. 나머지 복원 3개(고양이·인장·부두)를 256² + 목격담 스키마로 전환
3. **실제 완주 1회 + 소요 시간 측정** — 아직 한 번도 안 했다
4. 복원 5~8분 × 4개 = 20~32분 vs 목표 15~20분 **시간 충돌 해소**
5. 디에게틱 연출(작업대가 게임 세계 안으로) — 아직 착수 전
6. 월드 탐색(타일맵·이동) — 그 다음
