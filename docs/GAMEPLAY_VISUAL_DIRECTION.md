# 《안개항의 상속자》 게임 기능·디자인 방향

> 이 문서는 스토리 모드의 플레이 경험, 핵심 기능과 시각적 통일 기준을
> 정의한다. 세부 수치와 에셋은 프로토타입 검증에 따라 조정할 수 있지만,
> 게임의 중심 목적과 화면 언어는 이 문서를 기준으로 유지한다.

## 1. 게임의 중심 정체성

《안개항의 상속자》는 증언을 수집하고 그 내용을 그림으로 복원해 사건을
해결하는 픽셀 탐정 어드벤처다.

플레이 경험의 우선순위는 다음과 같다.

1. 그림 복원과 이미지 유사도 채점
2. 등장인물 탐문과 선택에 따른 단서 변화
3. 작은 월드의 탐색과 사물 상호작용
4. 두 엔딩으로 이어지는 증거 수집
5. 연출·사운드·부가 콘텐츠

핵심은 많은 기능이나 고해상도 이미지가 아니라 스토리, 진행, 상호작용,
그림 퀘스트와 디자인이 하나의 규칙으로 연결되는 완결성이다.

## 2. 핵심 게임 루프

```text
작은 픽셀 월드 탐색
→ 등장인물·사물과 상호작용
→ 대화 선택으로 증언과 단서 수집
→ 사무소의 1인칭 작업대에서 그림 복원
→ 원본 이미지와 유사도 채점
→ 결과가 월드·대사·장소 해금에 반영
→ 최종 증거 제시와 엔딩
```

복원 성공은 다음 퀘스트 버튼만 여는 것이 아니라 월드 안에서 확인할 수 있는
변화를 만든다.

- 경찰서 게시판의 용의자 그림이 갱신된다.
- 카버와 줄리언의 대사가 달라진다.
- 다음 조사 장소의 문이 실제로 열린다.
- 거리의 인물들이 사건 진행을 언급한다.
- 사무소 벽에 완성한 그림과 증거가 쌓인다.

## 3. 그림 복원·유사도 계산

그림 퀘스트는 게임의 가장 중요한 플레이 요소다. 기존 프로토타입의 다음
기술을 유지하고 스토리 퀘스트에 맞게 확장한다.

- 128×128 색칠판과 256×256 분석 이미지
- 제한 팔레트
- 불규칙 손상 영역
- 브러시, 채우기, 지우개, 실행 취소와 확대
- 색상·윤곽·주변 구조·팔레트 유사도
- CLIP 기반 의미 일치 보조 점수
- 실패 시 구체적인 재도전 피드백

시각 유사도는 통과 판정의 중심이며 CLIP은 의미 일치 보조로 사용한다. CLIP을
불러오지 못해도 시각 점수만 재정규화해 게임을 끝까지 진행할 수 있어야 한다.

세 메인 퀘스트는 같은 엔진을 사용하되 서로 다르게 느껴져야 한다.

### 초상 복원

- 연필 밑그림과 얼굴 윤곽 중심
- 표정의 비대칭, 흉터와 머리 모양이 핵심
- 초상과 카버의 얼굴을 겹쳐 비교하는 완료 연출

### 인장과 문신 복원

- 색보다 선과 형태의 정확도가 중요
- 문양 중심선과 대칭 보조 표시
- 진품·위조품을 겹쳐 차이를 드러내는 완료 연출

### 부두 현장 복원

- 세 퀘스트 중 가장 넓은 현장
- 가스등, 마차, 인물과 배의 위치 관계가 핵심
- 문양이 완성되면 해당 부분으로 확대되는 이벤트 연출

대화 선택에 실패했다고 통과 점수나 손상 범위를 몰래 높이지 않는다. 대신
얻을 수 있는 단서의 구체성, 증언 카드 수와 무료 힌트가 달라지게 해 난도
차이를 플레이어가 이해할 수 있도록 한다.

## 4. 대화와 스토리 분기

런타임 LLM API는 구현 복잡도, 검증 범위, 비용과 남은 개발 시간을 고려해
제출판에서 제외한다. 대화는 작가가 직접 통제하는 분기형 데이터로 구현한다.

대화 선택은 다음 네 가지 수사 행동을 중심으로 작성한다.

- 공감하며 기억을 끌어내기
- 구체적인 형태와 상황 캐묻기
- 진술의 모순 지적하기
- 확보한 증거 제시하기

각 중요 인물은 신뢰도, 압박도, 확인한 주제, 제시한 증거, 발견한 모순과 공개한
단서 상태를 가진다. 모든 대화를 거대한 트리로 만들지 않고, 선택에 따라 잠시
갈라졌다가 핵심 단서로 다시 합쳐지는 다이아몬드형 분기를 사용한다.

대화는 세 등급으로 구분한다.

1. 일반 대화: 세계관과 인물 성격을 보여주며 엔딩에 영향이 없다.
2. 퀘스트 단서 대화: 복원에 필요한 정보의 구체성을 바꾼다.
3. 핵심 판단 대화: 막마다 한 번 등장하고 결정적 증거 획득에 영향을 준다.

잘못된 선택은 즉시 게임 오버를 만들지 않는다. 다른 증거를 제시하거나 선택형
퀘스트를 수행해 회복할 수 있어야 한다.

## 5. 월드와 화면 전환

월드는 거대한 오픈 맵이 아니라 방향 감각을 유지할 수 있는 8~10개의 작은
화면으로 구성한다.

- 탐정 사무소
- 경찰서
- 아셔튼 저택 외부·응접실·유품 보관실
- 가정교사 홀트의 집
- 거리와 작은 광장
- 선술집
- 부두와 창고

화면 가장자리나 문을 통과하면 인접한 방으로 이어진다. 전환 후 플레이어의
진입 방향을 유지하고 짧은 페이드만 사용한다. 의미 없는 긴 이동보다 15~30초
마다 대화, 조사 지점 또는 작은 장면 변화가 나타나도록 상호작용 밀도를
우선한다.

화면은 세 가지 모드로 구분한다.

### 탐색 모드

- 3인칭 탑다운 픽셀 월드
- 단순한 걷기 애니메이션과 명확한 충돌 영역
- 방향키/WASD 이동, Enter/Space/E 상호작용
- 모바일 방향 패드와 상호작용 버튼

### 대화 모드

- 월드 배경을 유지하면서 카메라가 인물 쪽으로 확대
- 플레이어와 NPC의 작은 픽셀 초상 및 2~3단계 표정 변화
- 텍스트와 선택지에 집중하도록 주변 채도를 낮춤
- 핵심 판단 직전에는 음악과 주변 소리를 줄여 선택의 무게를 전달

### 복원 모드

- 탐정의 책상에 앉는 1인칭 화면
- 캔버스, 증언 카드, 팔레트와 도구를 하나의 작업대로 구성
- 월드보다 정보 밀도와 효과음이 높고 실제로 그림을 그리는 감각을 강조

## 6. 시각 디자인 원칙

디자인은 월드, 인물, UI, 폰트와 이벤트 화면까지 도트 스타일로 통일한다.
분위기와 구조의 참고점은 다음과 같다.

- 스타듀 밸리의 지나치게 어둡지 않은 생활 공간과 따뜻한 색감
- 언더테일의 절제된 픽셀 품질, 작은 방 연결과 밀도 있는 상호작용
- 레이튼 교수 시리즈의 미스터리 분위기와 퍼즐 진입의 특별함

위 작품의 캐릭터, 타일, UI, 로고나 구체적인 화풍을 복제하지 않는다. 생활감,
공간 구성, 단순함과 미스터리라는 추상적 설계 원리만 참고하고 모든 실제
에셋은 독자적으로 제작한다.

### 픽셀 규격

- 월드 가상 해상도: 480×270을 기준으로 검토
- 기본 타일: 16×16
- 월드 캐릭터: 약 16×24
- 대화 초상: 48×48 또는 64×64
- nearest-neighbor 확대
- 픽셀 에셋에 흐림 효과와 비의도적 안티앨리어싱 금지
- UI 테두리, 아이콘과 포커스 표시도 동일한 픽셀 배수 사용

### 색상과 분위기

- 월드 공통 팔레트는 약 20~24색
- 가스등의 따뜻한 황색, 청록빛 안개, 크림색 종이, 낮은 채도의 붉은색 사용
- 중요 인물마다 고유 강조색을 한 가지 정도만 부여
- 미스터리지만 공포 게임처럼 지나치게 어둡지 않게 유지

### 폰트

- 한국어 본문과 UI를 픽셀 폰트로 통일
- 기본 후보는 SIL Open Font License 1.1의 Galmuri11
- 큰 제목은 Galmuri14 사용 검토
- 최종 폰트 파일과 OFL 원문을 저장소에 함께 포함
- 작은 화면에서도 장문 대사가 읽히도록 자간, 행간과 최대 줄 길이를 우선 검증

## 7. 상대적으로 고품질인 이벤트 화면

평상시 화면을 의도적으로 절제하고 결정적인 순간에만 더 세밀한 픽셀 이벤트
화면을 사용한다. 일반 고해상도 일러스트로 갑자기 바꾸지 않고 같은 팔레트와
픽셀 규칙 안에서 디테일과 애니메이션만 늘린다.

권장 이벤트 화면은 최대 6개다.

1. 안개항과 아셔튼 저택 첫 등장
2. 카버의 첫 등장
3. 복원 초상과 카버 얼굴의 차이가 드러나는 순간
4. 인장과 문신의 공통점·차이가 연결되는 순간
5. 부두 복원에서 줄리언의 마차 문양이 드러나는 순간
6. 최종 증거 제시와 체포 또는 줄리언의 도주

이벤트 화면에는 큰 인물, 세밀한 배경, 제한적인 팔레트 확장, 안개·가스등·눈
깜빡임 같은 2~4프레임 애니메이션과 짧은 카메라 이동을 허용한다. 한 장면은
2~4초 안에 핵심을 전달하고 플레이어 입력으로 넘길 수 있어야 한다.

## 8. 자동 저장과 엔딩 기록

일반 자동 저장은 장소 이동, 단서 획득, 퀘스트 통과, 막 전환과 엔딩 도달 시
수행한다. 핵심 판단과 최종 증거 제시 직전에는 별도의 분기 체크포인트를 남긴다.

엔딩 이후 플레이어는 놓친 핵심 판단 직전으로 돌아가 다른 선택을 시도할 수
있다. 이미 확인한 엔딩 기록은 유지하며 타이틀에 `사건 기록 1/2` 또는
`사건 기록 2/2`를 표시한다.

## 9. AI 활용 범위

제출판에서 AI는 다음 범위로 제한한다.

- CLIP을 이용한 복원 이미지와 사건 설명의 의미 일치 보조 채점
- 개발 과정에서 생성 AI를 활용한 콘셉트 탐색과 에셋 제작 보조
- 코드·문서 제작에 사용한 AI 도구와 주요 프롬프트 기록

LLM 기반 실시간 NPC 대화는 제외한다. 생성 이미지를 최종 에셋으로 사용할
경우에도 게임의 픽셀 규격에 맞게 재작업하고, 도구·프롬프트·후처리·이용조건을
기록한다. 특정 작가나 게임의 화풍을 요구하는 프롬프트는 사용하지 않는다.

## 10. 개발 우선순위

1. 사건의 진실과 등장인물별 정보 범위 확정
2. 메인 대화와 핵심 판단 분기 작성
3. 필수 단서를 놓쳐도 진행 가능한지 검증
4. 세 복원 퀘스트의 원본·마스크·단서와 차별화 규칙 제작
5. 월드 탐색과 대화·복원 화면 전환 연결
6. 자동 저장, 체크포인트와 두 엔딩 구현
7. 공통 픽셀 에셋·폰트·UI 적용
8. 핵심 이벤트 화면과 최소 사운드 추가
9. 실제 완주 QA와 제출 자료 제작

## 11. 완성 기준

- 첫 플레이가 15~20분 안에 하나의 엔딩으로 자연스럽게 완결된다.
- 플레이어가 항상 현재 수사 목적과 다음 행동을 알 수 있다.
- 모든 메인 대화와 그림 퀘스트가 하나의 사건 해결 흐름에 기여한다.
- 잘못된 선택으로 진행이 영구적으로 막히지 않는다.
- 그림 퀘스트 세 개가 같은 엔진을 공유하면서도 서로 다르게 느껴진다.
- 월드, 대화, 작업대, 이벤트 화면과 폰트가 하나의 픽셀 디자인 언어를 따른다.
- 네트워크나 CLIP 모델 로딩에 실패해도 시각 채점만으로 완주할 수 있다.
- LLM API나 플레이어 개인 API 키 없이 모든 콘텐츠를 이용할 수 있다.
