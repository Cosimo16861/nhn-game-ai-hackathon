## 0. 무엇이 바뀌었나

| 폐기 | 대체 |
| --- | --- |
| 타일맵 월드 이동, 4개 구역, 미니맵 | **증거판 한 화면**(퀘스트 가지 맵) |
| NPC 자유 대화, 반복 질문, 4지선다 핵심 판단 | **비인터랙티브 컷신**(플레이어 개입 0) |
| 대화 선택으로 증언·증거 수집 | 컷신 종료 시 **자동 수집** |
| 엔딩 A / 엔딩 B 분기 | **단일 엔딩** |
| 분기 = 대화 선택 | 분기 = **퀘스트 가지**(어느 그림을 복원할지) |

플레이어가 내리는 결정은 이제 딱 하나로 수렴한다. **다음에 어느 그림을 복원할 것인가.**
그리고 그 결정의 근거는 직전 컷신에서 흘러나온 힌트다.

게임 루프:

```
컷신(자동, 힌트·증거 획득)
  → 증거판으로 복귀, 새 원이 압정에 꽂힌다
  → 원 하나를 고른다
  → 그림 복원 플레이
  → 통과
  → 다음 컷신
```

## 2. 해금 규칙

노드 상태는 셋이다.

| 상태 | 증거판에서 보이는 모습 |
| --- | --- |
| `LOCKED` | **아무것도 없다.** 빈 코르크판이다. 압정도 실도 그리지 않는다 |
| `OPEN` | 뒤집힌 종이(내용은 안 보임)가 압정에 꽂힌다. 제목만 표시 |
| `CLEARED` | 복원한 그림이 걸린다. 부모와 실이 이어진다 |

**레이어는 순차적으로 공개된다.** `L0`을 클리어하기 전에는 `L1`~`L6`이 화면에
존재하지 않는다. 레이어 열도, 열 이름도 그리지 않는다.

- 레이어는 그 안에 `OPEN` 이상인 노드가 하나라도 있을 때 처음 나타난다
- 같은 레이어 안에서도 아직 열리지 않은 노드는 보이지 않는다.
  본선만 따라온 플레이어에게 `L2`는 `2A`·`2C` 둘만 보이고 `2B`는 없는 것과 같다
- 간선은 **양 끝이 모두 보이고 부모가 `CLEARED`일 때만** 그린다.
  즉 실은 「끝낸 그림에서 아직 안 그린 종이로 뻗어 있는 단서」로 읽힌다

> 열은 왼쪽 기준 고정 피치다. 공개된다고 기존 노드의 위치가 움직이지 않는다.
> 오른쪽의 빈 코르크는 「아직 손대지 않은 사건」으로 읽히므로 채우지 않는다.

규칙:

1. `Q0`은 **오프닝의 마지막 컷(`C0B_THE_JOB`)이 끝나면** `OPEN`.
   그리고 증거판을 거치지 않고 곧바로 튜토리얼로 들어간다(4.1절).
2. 노드를 통과하면 그 노드의 **컷신이 재생되고**, 컷신이 끝난 뒤 자식 노드가 전부 `OPEN`이 된다.
3. **동시에 열린 원은 순서 자유.** 전부 플레이해도 되고, 하나만 골라도 된다.
4. 열린 원은 사라지지 않는다. 뒤 레이어로 진행한 뒤에도 언제든 돌아와 플레이할 수 있다.
5. `Q6_FINALE`은 `Q5A_DOCK` 통과로만 열린다. **가지만 플레이해서는 도달할 수 없다.**
6. `Q6` 진입 직전, 아직 `OPEN` 상태인 원이 남아 있으면 확인창을 띄운다.
   > 「증거판에 아직 비어 있는 압정이 있습니다. 지금 마무리하시겠습니까?」
   `UI.confirm()`을 쓴다(네이티브 `confirm` 금지).
7. 복원 실패는 상태를 되돌리지 않는다. 통과할 때까지 캔버스를 유지한 채 재제출한다.

### 2.1 막다른 가지의 처리

`Q2C`, `Q3B`, `Q4C`, `Q5B`는 자식이 없다. 통과하면 짧은 마무리 컷신이 나오고 증거판으로 돌아온다.
증거판에서는 이 노드에서 나가는 실이 **압정 없이 허공에서 끊긴다.** 더 볼 것이 없다는 신호다.

### 2.2 가지가 본선에 주는 것 — 보조 목격담

수직 슬라이스에서 코드로 검증된 핵심 메커니즘이 하나 있다.

> **증언으로 해금된 특징만 복원 목표에 뜨고 채점 필수가 된다.**
> 같은 그림이라도 플레이어가 아는 증언에 따라 목표의 개수가 달라진다.

그런데 이번 개정으로 증거가 컷신에서 **자동 수집**되면서, 본선만 따라가도 필요한 증언은
전부 들어온다. 그대로 두면 이 메커니즘이 작동은 하되 **플레이어마다 달라지지 않는다.**

그래서 다음 규칙을 둔다.

- 가지는 **결정적 증거를 주지 않는다**(변경 없음). 엔딩과 진행에 영향이 없다
- 대신 가지는 본선 복원 퀘스트에 **보조 목격담**을 줄 수 있다.
  보조 목격담은 채점 필수 특징이 **아니며**, 목표 패널에 한 줄 더 뜰 뿐이다
- 즉 가지를 플레이한 사람은 **같은 그림을 더 쉽게** 그린다. 다른 결말을 얻지는 않는다

| 가지 | 보조 목격담 | 받는 본선 노드 |
| --- | --- | --- |
| `Q2C_CHILD_ROOM` | 크레용 그림 속 아이가 자기 머리를 아주 짙게 칠해 놓았다 | `Q2A_TRUE_FACE` — 머리색 |
| `Q3C_WAREHOUSE` | 창고 앞 상자 배치와 젖은 돌바닥을 직접 봤다 | `Q5A_DOCK` — 배경 배치 |
| `Q4B_LOGBOOK` | 일지에 마차가 선 자리가 적혀 있다 (「가스등 두 번째 기둥 옆」) | `Q5A_DOCK` — 마차 위치 |

### 🔴 금지 사항 — 가지가 앞질러 말하면 안 되는 것

**가지는 본선 `Q2A`도 안 본 플레이어가 도달할 수 있다.** `Q1B → Q2B → Q3C → Q4B → Q5B`는
본선을 하나도 밟지 않고 다섯 칸을 갈 수 있는 체인이다. 따라서:

- 보조 목격담이 `Q3A`의 **파도 세 줄**이나 `Q5A`의 **마차 문양**을 알려주면 안 된다
- 가지 컷신에서 **줄리언·아셔튼이라는 이름이 배후로 지목되면 안 된다.**
  `Q4B`의 항해일지가 주는 것은 마차가 선 **위치**까지다
- 이 둘은 예외 없이 **본선 복원으로만** 드러난다. 어기면 `Q5A`의 반전이 통째로 무력해진다

### 2.3 가지에 갇히지 않게 하는 장치

선술집 체인을 계속 타면 사건이 멈춘 채 다섯 장을 연달아 그리게 된다.
「나 지금 수사 중인 거 맞나」 하는 이탈 구간이다.

**가지 컷신 끝에 본선을 상기시키는 대사 한 줄을 둔다.** 「저택은 안 가 봐도 돼요?」,
「봉인은 언제 보러 가시오?」 같은 것이다. 어느 원이 본선인지는 여전히 표시하지 않는다 —
등장인물이 궁금해할 뿐이다.

## 3. 증거판 — 퀘스트 가지 화면

퀘스트 가지 맵은 별도의 UI 화면이 아니라 **탐정 사무소 벽의 코르크 증거판**이다.
게임 세계 안의 물건으로 그려야 한다(디에게틱 원칙).

- 원 = 압정에 꽂힌 종이/그림. 통과한 노드는 실제 복원 결과 이미지의 축소본이 걸린다
- 간선 = 실. **본선은 붉은 실**, 가지는 **흰 실**. 실은 중력을 받아 살짝 처진다
- 레이어 = 왼쪽에서 오른쪽으로, 고정 피치 7열
- **잠긴 노드는 그리지 않는다**(2장 참조). 오른쪽은 빈 코르크로 남는다
- 배경은 사무소 벽. **창밖 안개가 본선 진행도에 따라 걷힌다**(`fogLevel`, 구현 완료)

### 3.3 구현 (완료)

**화면 전체가 640×384 캔버스 한 장이다.** HTML 패널을 섞지 않는다.
섞는 순간 화면이 둘로 쪼개져 "게임 + 웹사이트"로 보인다. 파일은 셋이다.

| 파일 | 역할 |
| --- | --- |
| `src/screen.js` | **모든 화면이 공유하는 프레임.** 정수배 확대, 팔레트, 고해상도 글씨, 음영·패널 프리미티브, 접근성 핫스팟 |
| `src/office.js` | 탐정 사무소 자체 — 벽·창·아날로그 시계·몰딩·책상·스탠드·필기도구 |
| `src/branchmap.js` | 그 벽에 걸린 코르크판과 종이·압정·실 |

```js
BranchMap.mount(el, { onSelect(nodeId) {}, reserveHeight: 76 });
BranchMap.render(State, { clock });             // State.has(flag) 만 읽는다
BranchMap.setThumbnail(id, canvas);             // 통과 시 결과 축소본 등록
```

컷신·작업대도 `PixelScreen` + `Office`를 그대로 쓴다. 그래야 세 화면이
한 프레임으로 이어진다.

#### 프레임에서 반드시 지킬 것

- **정수배 확대만.** 1.37배 같은 배율은 픽셀을 들쭉날쭉하게 만든다.
  창에 맞춰 1·2·3배 중 하나로만 키우고 남는 공간은 여백으로 둔다
- **한글은 전용 3배 해상도 레이어에 그린다.** 640×384에서 1비트로 이진화하면 작은
  한글 획이 붙거나 끊어진다. 배경은 저해상도 픽셀 캔버스에 유지하고,
  `PixelScreen.text()`만 투명 고해상도 캔버스에 안티앨리어싱으로 그린다.
  장식용 1비트 글씨가 꼭 필요한 곳만 `{ mode: "pixel" }`을 쓴다
- **음영은 `fade`/`glow`로.** 한 색을 넓게 디더로 깔면 계조가 아니라 체커보드로 보인다.
  **가까운 톤을 여러 겹 쌓아야** 부드러워진다(실제로 겪은 함정. 코르크 오른쪽
  어두운 면은 `corkDark → corkGrain → corkHole` 3겹이다)
- **난수는 전부 씨앗 고정.** 코르크 알갱이·나뭇결·종이 기울기가 다시 그릴 때마다
  달라지면 화면이 떨린다
- **팔레트는 `PixelScreen.PAL`에만.** 즉흥으로 색을 만들지 않는다

#### 접근성

보이는 것은 전부 캔버스지만, 누를 수 있는 것은 그 위에 **투명한 DOM 버튼**으로 겹친다.
키보드 이동과 스크린 리더가 그대로 동작하고, 포커스 표시는 캔버스에 금색 점선으로
다시 그린다(CSS `outline`을 쓰면 거기만 웹처럼 보인다).
`CLEARED` 노드는 `disabled` — 끝낸 그림은 탭 이동에서 빠진다.

#### 그 밖의 구현 결정

- 열 좌표 고정(`COL_X`), 행은 이야기 줄기별 4행(`ROW_Y`), 종이 40×28
- 종이는 노드 id 해시로 ±2px 흔들어 손으로 꽂은 느낌을 낸다
- 라벨은 종이 **바깥**에 그린다. 길면 띄어쓰기에서 두 줄로 접는다.
  판에 적는 짧은 이름은 `BOARD_TITLE`, 정본 제목은 `quest-graph.js`
- 축소본이 없으면 노드 id로 절차 생성한 자리표시를 그린다
- **창밖 안개는 본선 진행도에 따라 걷힌다**(`fogLevel`). 옅어지면 지붕선과
  가로등이 드러난다
- 확인용 화면: `board.html` — 단계를 앞뒤로 밀며 순차 공개를 눈으로 볼 수 있다

미구현: 실제 복원 결과 연동(`setThumbnail` 호출부는 작업대 재작성 때 붙는다).

> 이 화면은 엔딩 이미지와 같은 물건이다. 게임 전체가 "증거판을 채워 붉은 실을 잇는 일"이 되고,
> `Q6_FINALE`에서 마지막 실이 이어지는 순간이 곧 엔딩 컷이다. 별도의 엔딩 연출 자산이 줄어든다.

### 3.1 표시하지 않는 것

- 어느 원이 본선인지 **직접 표시하지 않는다.** 실 색(붉은/흰)은 통과한 뒤에만 칠해지므로,
  선택 시점에는 단서가 되지 않는다
- 점수, 진행률 퍼센트, 남은 원 개수는 표시하지 않는다(숫자 비공개 원칙)
- 잠긴 노드의 제목은 표시하지 않는다

## 4. 컷신 시스템

컷신은 퀘스트와 퀘스트를 잇는 **비인터랙티브 애니메이션**이다(이미지 + 대사).
스토리 전개 전체가 여기서 일어나며, 플레이어는 개입하지 않는다.

### 4.1 게임 전체 흐름

```
게임 실행
  → C0_INTRO       인트로 (세계와 인물)
  → C0B_THE_JOB    발단 (리드가 일감을 가져온다)
  → Q0 튜토리얼 플레이            ← 증거판을 거치지 않고 바로 들어간다
  → C1_THE_CASE    다음 스토리 + L1의 당위
  → 증거판 (메인 화면) — 여기서 처음 등장한다
  → L1 원 선택 → 플레이 → 클리어
  → 그 원의 컷신 (다음 레이어의 당위)
  → 증거판 → L2 …
  → Q6 클리어
  → CE_ENDING      엔딩
```

**증거판이 처음 나오는 시점은 `C1_THE_CASE` 직후다.** 그때 판에는 이미 플레이어가
그린 그림 한 장이 걸려 있고 뒤집힌 종이 두 장이 새로 꽂힌다. 화면 하나로
「끝낸 것 / 안 한 것 / 실」의 언어를 전부 가르친다.
튜토리얼 전에 판을 보여주면 종이 한 장뿐이라 그 언어가 전달되지 않는다.

### 4.2 컷신 4종

종류마다 하는 일이 다르다. 대본을 쓸 때 자기가 어느 종류인지부터 정한다.

| 종류 | 언제 | 하는 일 | 개수 |
| --- | --- | --- | :--: |
| `opening` | 게임 시작 | 세계·인물·발단. 튜토리얼로 직행 | 2 |
| `bridge` | 노드 클리어 후 | **다음 레이어의 당위**를 준다. 증거판 복귀 | 10 |
| `closing` | 막다른 가지 클리어 후 | 실을 끊고 마무리. 해금 없음. 증거판 복귀 | 4 |
| `ending` | `Q6` 클리어 후 | 대질·엔딩·후일담 | 1 |

**총 17개.** `bridge`와 `closing`은 노드에 1:1로 붙는다(노드 15개 = 컷신 15개).

### 4.3 컷신이 반드시 지켜야 할 네 가지

**① 자기가 해금하는 모든 노드의 당위를 담는다.**
`C2A`가 `Q2A`·`Q2C` 둘을 열면, 그 컷신 안에 **두 그림 각각을 왜 그려야 하는지**가
나와 있어야 한다. 하나라도 빠지면 플레이어는 근거 없이 원을 고르게 된다.

**② 형제 노드의 클리어 순서에 의존하지 않는다.** ← 가장 틀리기 쉬운 곳

같은 레이어의 원은 **아무 순서로나** 깰 수 있다. `Q2C`를 먼저 깨고 `Q2A`를 나중에 깰
수도 있고 그 반대일 수도 있다. 그러므로 컷신 대사가 형제의 상태를 단정하면 안 된다.

```
✗ 「홀트 선생은 아직 안 만나 보셨죠?」   ← Q2A 를 이미 깼으면 거짓말이 된다
○ 「홀트 선생은 만나 보셨어요?」          ← 어느 쪽이든 성립한다
```

단정이 꼭 필요하면 **조건부 비트**를 쓴다(4.4의 `when`).

**③ 결정적 사실을 앞질러 말하지 않는다.** 2.2절의 금지 사항 참조.
가지는 본선을 하나도 밟지 않은 플레이어가 도달할 수 있다.

**④ 막다른 가지(`closing`)는 본선을 상기시키고 끝낸다.**
「저택은 안 가 봐도 돼요?」류의 한 줄. 어느 원이 본선인지는 표시하지 않는다.

### 4.4 데이터 스키마

```js
{
  id: "C3A_THE_SEAL_HE_DREW",
  kind: "bridge",                   // opening | bridge | closing | ending
  place: "police-station",          // 배경 키 (GAME_DESIGN 7.3)
  beats: [
    { who: "lead",   face: "tense", text: "…", ms: 2600 },
    { who: "player", face: "calm",  text: "…", ms: 2200 },
    { who: "carver", face: "high",  text: "…", ms: 3000, sfx: "chalk" },
    // 조건부 비트 — 플래그를 만족할 때만 재생한다
    { who: "cora", face: "calm", text: "저택은 안 가 봐도 돼요?", ms: 2400,
      when: { unless: "NODE_CLEARED_Q1A_IDEALIZED" } },
  ],
  grants: ["EV_CARVER_SEAL_4WAVES"],   // 종료 시 일괄 적용
  unlocks: ["Q3A_SEAL", "Q3B_TATTOO"], // quest-graph 의 UNLOCKS 와 일치해야 한다
}
```

`when`은 `{ if: flag }` 또는 `{ unless: flag }`다. 엔딩의 후일담 변주
(`EPILOGUE_CUTS`)도 같은 장치를 쓰므로 재생기는 어차피 이걸 구현해야 한다.

### 4.5 진행과 조작

- **선택지 없음. 자동 진행.** 비트마다 표시 시간(`ms`)이 정해져 있다
- 클릭/스페이스: 타이핑 즉시 완료 → 한 번 더 누르면 다음 비트
- ESC: 전체 스킵. **그 컷신을 한 번 끝까지 본 뒤에만** 활성화한다
- 종료 → 증언·증거 카드가 쌓이는 짧은 연출 → 증거판 복귀
  (단 `opening`의 마지막 컷은 튜토리얼로 직행)

### 4.6 원자성과 재개 — 빠뜨리면 진행이 막힌다

**컷신은 원자적이다.** `grants`와 해금은 **끝까지 본 시점에 한 번에** 적용된다.
중간에 창을 닫으면 아무것도 반영되지 않는다.

그래서 재개할 때 이런 상태가 생긴다 — **퀘스트는 통과했는데(`NODE_CLEARED_X`)
그 컷신은 안 본(`CUTSCENE_SEEN_X` 없음)** 노드. 이걸 그냥 두면 자식 노드가 영영
열리지 않아 진행이 막힌다.

```js
QuestGraph.pendingCutscene(State)  // 재개 시 먼저 재생할 컷신. 없으면 null
```

동시에 대기하는 컷신은 **최대 하나**다(클리어 즉시 재생되므로).
게임을 켤 때 이 값이 있으면 증거판보다 먼저 그 컷신을 재생한다.

### 4.7 화면 구성

언더테일식 — **텍스트 박스가 주인공**이고 초상은 보조다. 장면은 컷 단위로 툭툭 끊긴다.

- 배경: 장소 일러스트 1장(정지, 매우 느린 패럴랙스 허용)
- 좌하단: 플레이어 초상 · 우상단: 상대 초상 (64×64 원본, 화면 96×96)
- 하단: 대화창 448×112, 최대 3줄, 한 줄 한글 24~28자
- 표정 3종: `calm` / `tense` / `high`
- 말하지 않는 쪽 초상은 채도·명도를 낮춘다
- 전부 `PixelScreen` + `Office` 위에 그린다(3.3절의 프레임 규칙)

### 4.8 분량과 제작 물량

| 종류 | 비트 수 | 길이 | 개수 |
| --- | --- | --- | :--: |
| `opening` | 8~12 | 40~60초 | 2 |
| `bridge` (본선) | 10~16 | 50~80초 | 5 |
| `bridge` (가지) | 5~9 | 25~45초 | 5 |
| `closing` | 4~8 | 20~40초 | 4 |
| `ending` | 24~30 | 120~150초 | 1 |

컷신 총량이 곧 스토리 전개량이다. 본선 경로만 따라가면 약 8분.

**codex가 만들 물량** — 반복 작업이므로 표로 못박아 둔다.

| 자산 | 수량 | 비고 |
| --- | ---: | --- |
| 컷신 데이터 | 17 | 대본은 `docs/script/07_CUTSCENES.md`에 전부 있다 |
| 배경 | 10 | `GAME_DESIGN` 7.3. `office`는 `Office.drawRoom()` 재사용 |
| 초상 | 11명 × 3표정 = 33 | 64×64. 베스·램은 1표정으로 줄여도 된다(→ 29) |

## 5. 시간 예산 (재산정)

기존 목표 15~20분은 **월드 탐색·대화가 시간의 절반을 쓰던 구성**의 수치다.
그 둘을 없애고 복원 퀘스트를 3개에서 14개로 늘렸으므로 그대로 쓸 수 없다.
(15개 노드 중 `Q6_FINALE`은 복원이 아니다)

| 구간 | 시간 |
| --- | ---: |
| 인트로 + 튜토리얼 | 4분 |
| 본선 복원 5개 (Q1A·Q2A·Q3A·Q4A·Q5A) | 22~27분 |
| 본선 컷신 6개 | 5분 |
| 엔딩 | 4분 |
| **본선 완주** | **약 35~40분** |
| 가지 8개 + 컷신 | +22~28분 |
| **전체 완주** | **약 55~65분** |

**확정 방침**: 목표를 **본선 완주 30~35분 / 전체 60분 내외**로 상향한다.
15~20분으로 되돌리려면 본선 복원을 5개에서 3개로 줄여야 하는데, 그러면 레이어가 5개가 되어
요구된 6~8 레이어를 만족하지 못한다. 대신 다음으로 조인다.

- 캔버스 크기를 노드별로 차등한다. **모든 복원이 256²일 필요는 없다**
  - 튜토리얼·소형 가지: 64² 또는 96²
  - 중형(문신·봉인·일지·장부): 128²
  - 대형(초상 2개·부두): 256²
- 대형 복원은 **인물 전체 채색**, 중형 이하는 **핵심 영역만** 칠하도록 선화 밀도를 조절한다
- 팔레트를 노드당 5~8색으로 제한해 탐색 시간을 줄인다

## 7. 스토리 구조상 반드시 지켜야 할 한 가지

재구성 과정에서 기존 설정의 결함 하나를 고쳤다. **되돌리면 추리가 무너진다.**

기존 설정에서는 줄리언이 카버에게 "불완전한 모사"를 가르쳐 파도가 네 줄이 됐다고만 했다.
왜 가문의 재산 관리인이 자기 가문 인장을 틀리게 아는지 설명되지 않았다.

**수정된 설정**:

- 아셔튼 **본가** 인장 = 초승달 아래 파도 **세 줄**. 엘리너가 보관하며 12년째 쓰이지 않았다
- 줄리언은 **방계** 혈통이다. 그의 마차·문구류에는 방계 문장인 파도 **네 줄**이 새겨져 있다
- 줄리언은 본가 인장 실물을 본 적이 없다. 카버를 가르칠 때 **자기 마차 문의 문양을 보여줬다**

그래서:

| 그림 | 드러나는 것 |
| --- | --- |
| `Q3A_SEAL` 진품 봉인 | 파도 **세 줄** → 카버가 그린 네 줄은 가짜 |
| `Q5A_DOCK` 마차 문양 | 파도 **네 줄** → 카버에게 가르친 자는 **그 마차의 주인** |

증언이 아니라 **플레이어가 직접 복원한 두 그림의 대조**가 범인을 지목한다.
이것이 이 게임이 그림 복원 게임인 이유이며, 본선 루트가 본선인 이유다.
