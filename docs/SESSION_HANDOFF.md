## 1. 한 문단 요약

**게임 시스템이 크게 바뀌었다.** 시간 제약으로 월드 탐색과 대화 분기를 통째로 폐기하고,
그림 복원 하나에 집중하는 **퀘스트 가지 구조**로 재구성했다. 스토리는 퀘스트 사이에
자동 재생되는 **비인터랙티브 컷신**으로 전개되고, 증거는 컷신 종료 시 자동 수집된다.
엔딩은 하나다. 설계 문서 재작성과 그래프 데이터 작성은 끝났고 **구현은 착수 전**이다.

### 검증한 것

`node`로 `quest-graph.js`를 직접 돌려 확인했다.

```
정합성 문제: 0 · 노드 15 · 레이어당 본선 정확히 1개
도달 가능 노드: 15/15
가지만 플레이 시 엔딩: locked  ← 본선 루트가 하나임이 코드로 보장됨
실: 붉은 6 / 흰 8
```

`QuestGraph.validate()`는 컷신 `UNLOCKS` 표와 노드 `parents`가 어긋나면 콘솔 경고를
남긴다. 대본과 데이터가 따로 놀지 않도록 부팅 시 1회 호출할 것.

증거판은 브라우저에서 직접 눌러 확인했다(`board.html`, 콘솔 에러 0).

```
인트로만 봄 → Q0 하나만 보인다. L1~L6 없음
Q0 클리어  → L1의 Q1A·Q1B 두 장이 나타난다
Q1A 클리어 → L2에 Q2A·Q2C 만 나타난다. Q2B는 Q1B를 안 했으므로 없다
열린 종이 클릭 → onSelect(nodeId) 정상
```

## 4. 🚧 다음 세션이 먼저 결정할 것

### 4-1. 복원 타깃 아트 방향 (이전 세션부터 이어진 미결)

`assets/`의 회화풍 초상은 채우기식 복원에 쓸 수 없다는 것이 실측으로 확인됐다.
상위 10색이 전부 미세하게 다른 갈색이고 최대 영역이 16,381px라 클릭 한 번에 대부분이
칠해진다. 밀랍 봉인(`20-broken-wax-seal.png`)처럼 평면적인 자산만 정상 분해된다
(선화 15,488px, 영역 3개). **파이프라인은 정상이고 원본 아트가 조건 미달이다.**

선택지:

1. **절차 생성으로 평면 초상을 그린다** ← 유력.
   영역·특징 위치를 정확히 통제할 수 있다. 복원 대상은 「증언으로 재구성한 그림」이라
   사실적일 필요가 없고, 평면 도트가 오히려 콘셉트에 맞는다
2. 평면 채색 아트를 따로 준비한다 (품질 최선, 아트 작업 선행)
3. 회화풍 원본을 포스터화 + 윤곽검출로 평면화 (결과가 지저분할 가능성 높음)

`quest-portrait.js`의 `drawSource()`를 통째로 교체하면 된다.
`source`가 `(ctx, size, {loadImage}) => void` 계약만 지키면 `artwork.js`·
`restoration.js`는 손대지 않아도 된다.

### 4-2. 복원 퀘스트 9개 신규 제작의 아트 부담

가지가 늘어 복원 대상이 4개에서 14개가 됐다. 4-1의 결정이 9개 전부에 영향을 준다.

## 6. 확정된 설계 (되돌리지 말 것)

### 6-1. 이야기

- **인장 파도 세 줄/네 줄 설정.** 본가 = 세 줄, 줄리언의 방계 = 네 줄.
  줄리언은 본가 인장 실물을 본 적이 없어 카버에게 자기 마차 문양을 가르쳤다.
  `Q3A_SEAL`과 `Q5A_DOCK` **두 복원물의 대조가 배후를 지목한다.**
  이 게임이 그림 복원 게임인 이유이자 본선이 본선인 이유다. 되돌리면 추리가 무너진다
- **단일 엔딩.** 가지는 결정적 증거를 절대 주지 않는다. 대신 후일담 컷으로 보상한다
- **컷신에 선택지 없음.** 증거는 컷신 종료 시 일괄 적용되므로 놓칠 수 없다

### 6-2. 시스템

- **복원 결과에 숫자를 절대 노출하지 않는다.** 정성 피드백 4단계만.
  `scripts/score-manager.js`는 숫자를 노출하는 폐기 스펙
- **네이티브 `confirm()`/`alert()` 금지.** 차단 환경에서 조용히 실패한다. `UI.confirm()`
- **CLIP 제외.** 외부 네트워크 의존 0. `scripts/clip-*.js`는 미사용으로 남겨 둠
- **복원 목표는 설계 용어가 아니라 목격담으로 표시한다**
  ```
  이전: ◆ 왼눈썹 비대칭
  이후: "웃을 때요, 왼쪽 눈썹만 유독 위로 올라갔습니다." — 홀트
  ```
- **진행 화면은 디에게틱해야 한다.** 퀘스트 가지 맵 = 사무소 벽의 코르크 증거판.
  이 화면이 곧 엔딩 이미지다

### 6-3. 사용자가 직접 고른 결정

| 질문 | 선택 | 함의 |
| --- | --- | --- |
| 256²에서 플레이어는 무엇을 그리는가 | **인물 전체를 채색** | 선화만 제공하고 전체를 채운다. 단, **256²는 `Q1A`·`Q2A`·`Q5A` 세 개뿐**이고 나머지는 16²~128²다(`GAME_DESIGN` 8.6) |
| 정답 그림은 무엇으로 만드는가 | 기존 자산 활용 + 절차 생성 | 전제("기존 자산을 쓸 수 있다")가 4-1에서 무너졌다. 초상에 한해 절차 생성이 자연스러운 귀결이나 사용자 확인이 필요하다 |

## 7. 코드에만 있고 눈에 안 띄는 구현 결정

- **채우기 도구는 영역 데이터가 없어도 동작한다.** `regionOf`가 있으면 그것을,
  없으면 런타임 flood fill(`restoration.js`의 `regionCells`)
- **색을 골라도 도구가 바뀌지 않는다.** 지우개·스포이드 상태였을 때만 채우기로 복귀
- **격자는 칸이 6px 미만이면 자동으로 숨는다.** 격자선은 CSS 오버레이
- **256²에서는 기본 도구가 채우기**, 그 이하에서는 연필
- **외곽선 색은 양자화 팔레트에 자동 추가된다**(빠뜨리면 선화가 생기지 않는다)

### 퀘스트 데이터 스키마 (256² 기준)

```js
window.QuestPortrait = Object.freeze({
  id: "REST1", gridSize: 256,
  source: drawFn,          // (ctx, size, {loadImage}) => void, async 가능
  outline: "#241C17",      // 선화 색 (플레이어가 고를 수 없음)
  minRegion: 24,
  palette: [{ name, hex }],
  requiredFeatures: [{
    id, clue|always, color,   // color → 그 색으로 칠할 픽셀이 자동 산출됨
    label, speaker, quote, missNote,
  }],
  weights, passingScore,
});
```

### 진행 플래그 규약

- `NODE_CLEARED_<노드ID>` — 복원 통과
- `CUTSCENE_SEEN_<컷신ID>` — 컷신 종료. **해금의 실제 트리거**

## 9. 현재 동작 상태

폐기 예정인 옛 빌드(프롤로그~두 엔딩)가 아직 돌아간다. 재구성 구현이 시작되면
`src/dialogue.js`와 `src/data/dialogue-*.js`가 화면에서 빠진다.
**대사 텍스트는 컷신 대본의 원본이므로 파일을 삭제하지 말 것.**

- 고양이 퀘스트(16×16): 정상
- 초상 퀘스트(256²): 목격담 표시는 되지만 채우기 영역이 잘못된 절반 상태 (4-1이 원인)
- 옛 엔딩 A/B 판정: 동작하지만 **단일 엔딩으로 대체될 예정**
